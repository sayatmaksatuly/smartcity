# AITU KEREK — город ближе

## Phase 5 — места, пешеходные маршруты и личные сохранения

Новый лаймовый интерфейс сохраняет простой путь: запрос → рекомендации → карта по действию пользователя. Есть пешеходный routing через backend/openrouteservice, добровольная геолокация с точностью и ручным стартом, отдельный маршрут к каждому месту и проверка прогулки из выбранных по порядку остановок. Карточки по-прежнему показывают оценки по прямой; дорожный маршрут и его ETA отображаются отдельно.

Добавлены Supabase Auth (email/пароль, подтверждение, восстановление, сессия), профиль, избранное и сохранённые прогулки. Гостевой поиск, чат и карта доступны без регистрации. GPS, текст чата и геометрия маршрута не сохраняются в Supabase. SQLite остаётся источником 549 реальных OSM-мест.

**Внешняя настройка ещё требуется:** `ORS_API_KEY` отсутствует, поэтому живой маршрут не подтверждён. Supabase Auth отвечает, но пользовательские таблицы пока отсутствуют либо не открыты через API. Примените SQL migration из `supabase/migrations` в существующем проекте и настройте redirects по [инструкции Supabase](docs/PHASE5_SUPABASE.md). Полный email-flow и изоляция двух живых аккаунтов до этого не подтверждены. Подробные результаты и ограничения: [отчёт Phase 5](docs/PHASE5_COMPLETE_REPORT.md).

### Историческая основа Phase 4

Главная начинается с «Куда хотите сходить?»: запрос → **«Найти место»** → до трёх вариантов. **«Подобрать прогулку»** открывает время и интересы, **«Спросить помощника»** — существующий контекстный диалог. Карта загружается только по явному действию: «Показать на карте», «На карте» или выбор старта на карте. Возврат на главную, к результатам и в диалог сохраняет состояние вкладки; браузерная кнопка «Назад» тоже работает.

Точка по умолчанию явно обозначена как центр Астаны. Изменить её можно по названию, координатам, отдельным выбором на карте или добровольной геолокацией. Случайный клик при просмотре карты больше не меняет старт. Каждая карточка — отдельный вариант, расстояния и время остаются приблизительными, без построения дорожного маршрута.

Историческая проверка Phase 4: **145 pytest, 35 Playwright**; [подробный отчёт и снимки](docs/PHASE4_PRODUCT_AUDIT.md). Актуальные проверки Phase 5 перечислены в [новом отчёте](docs/PHASE5_COMPLETE_REPORT.md).

Локальный MVP городского проводника по Астане для команды Build with AI Hackathon 2026, Astana IT University. Выберите старт, время и интересы — получите до трёх реальных мест с источником, расстоянием по прямой и приблизительным бюджетом времени. Каждый результат — отдельный вариант прогулки, не общий маршрут.

**Данные действительно собираются автоматически:** CLI отправляет ограниченный запрос Overpass, нормализует OSM-объекты и записывает SQLite. В проверенной рабочей базе — 549 POI из 554 полученных объектов после дедупликации, включая многоязычные названия. Старт приложения не добавляет фиктивных мест; тестовые fixtures изолированы от основной базы.

## Быстрый запуск на Windows 11

Нужны Python 3.11+ и Node.js 24 LTS (с npm). Фактически проверено на Python 3.14.4, Node 24.19.0. Установки Python и Node должны быть доступны в PATH. Для установки зависимостей, импорта, подложки карты и Gemini нужен интернет. После импорта локальный подбор работает без интернета; карта без сети может остаться без подложки.

В PowerShell из корня проекта:

```powershell
Set-Location 'C:\Users\ПК\Desktop\aitu-kerek-smartcity'
.\scripts\setup.ps1
.\scripts\import-pois.ps1
.\scripts\start.ps1
```

Если политика PowerShell блокирует локальные скрипты, запустите конкретный скрипт в отдельном процессе:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\import-pois.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Это не меняет постоянную политику компьютера. Скрипт setup создаёт `.venv`, устанавливает зафиксированные зависимости и копирует `.env.example`, если `.env` ещё нет. `start.ps1` запускает backend в скрытом процессе, frontend — в текущем терминале; Ctrl+C останавливает их. Скрипт сообщает о занятых портах, не завершает посторонние процессы. Backend-логи без access-log лежат в `.runtime`.

- Приложение: [localhost:5173](http://localhost:5173)
- API: [localhost:8000/api/health](http://localhost:8000/api/health)
- Swagger: [localhost:8000/docs](http://localhost:8000/docs)

Можно открыть `127.0.0.1` вместо `localhost`. Серверы слушают только локальный интерфейс.

## Контекстный помощник — Phase 3

Откройте «Спросить помощника» на главной. Например: «Хочу погулять, у меня два часа» → «Возле Байтерека» → подтвердите старт → «Красивые места, но без кафе» → «Поближе, теперь 30 минут». Чат сохраняет ограничения, синхронизирует фильтры, карточки и карту. Поддерживаются «ещё варианты», возврат к предыдущим и повторный выбор места. Старт по названию всегда требует подтверждения.

Память — только в текущей вкладке: восемь сообщений и ограниченное структурированное состояние. «Новый диалог» очищает контекст и фильтры, сохраняя явно выбранную точку. При активном диалоге обычная кнопка поиска также сохраняет его условия; после сброса обычный поиск работает независимо. Без Gemini доступен честно обозначенный локальный подбор. Произвольная беседа вне подбора мест ограничена.

[Архитектура, результаты Phase 3 и сценарий демонстрации на 60–90 секунд](docs/PHASE3_REPORT.md). Ограниченный smoke диалога: `.venv/Scripts/python.exe scripts/chat_smoke.py --require-gemini` — ровно две генерации; не запускайте его в цикле. Ключ остаётся в backend.

## Gemini

Необязательный ключ добавьте в **`backend/.env`**:

```dotenv
GEMINI_API_KEY=
GEMINI_MODEL=gemini-flash-latest
```

Впишите собственное значение после `GEMINI_API_KEY=` и перезапустите backend. Не добавляйте ключ в frontend, `VITE_*`, Git или скриншоты. Имя модели настраивается: алиас может меняться у провайдера. SDK — официальный `google-genai`; генерация использует `GenerateContentConfig(response_json_schema=GeneratedPlan.model_json_schema())` со строгой последующей Pydantic-валидацией и проверкой POI. [Документация Google Gen AI](https://googleapis.github.io/python-genai/).

Без ключа появляется **«Подбор без ИИ»**. При ошибке ключа, лимите, таймауте или недопустимом ответе Gemini приложение возвращает локальный подбор с объяснением сбоя. Наличие ключа в статусе не означает проверенную доступность API. Серверная диагностика разделяет `call`, `parse` и `grounding`, выводя только фиксированный код ошибки и числовой HTTP-статус. Реальный `mode=gemini` подтверждён 17 октября 2026 через `/api/recommendations` с существующим серверным ключом; [результаты проверки и причина исправленного HTTP 400](docs/VERIFICATION.md).

## Как пользоваться

1. Введите запрос на главной или откройте «Подобрать прогулку» для выбора времени и интересов. Старт по умолчанию — центр Астаны; изменить его можно по кнопке точки старта.
2. Введите запрос, укажите время и интересы. Структурные фильтры времени/категории и выбранный старт имеют приоритет над текстом.
3. «Уточнить прогулку» позволяет выбрать велосипед, возвращение, бесплатный вход по `fee=no` и открытие по поддерживаемому расписанию OSM.
4. Нажмите «Найти место» или «Подобрать места». Откройте карту отдельной кнопкой, выберите метку и вернитесь к результатам. Выбор места синхронизирован с карточками.
5. В «О месте и данных» видны источник, импорт, расписание и неопределённости.

Для Mega Silk Way найдите `Mega` в поиске старта или напишите «Я возле Mega Silk Way». После поиска приложение предложит подтвердить найденный старт; координаты меняются только по кнопке. Фразы «40 минут», «два часа», «полчаса» и «30–60 минут» разбираются. При расхождении с выбранным временем интерфейс предлагает применить время из текста, сохраняя текущий фильтр до подтверждения. API без явного `duration_minutes` использует распознанное время, иначе 60 минут.

Сочетания «кофе и погулять», простые отрицания «не хочу кафе, лучше парк», отдых и туристические интересы обрабатываются отдельно. Есть небольшой словарь английских и казахских формулировок. Конфликты показываются рядом с результатами. Gemini получает разобранные намерения и реальные кандидаты, без исходного пользовательского текста и точных координат.

## Данные

Импорт: `scripts/import-pois.ps1`. Область: 51.00–51.25 N, 71.25–71.65 E. Категории: парки/скверы, культура, достопримечательности, кафе, активности, библиотеки/торговые центры. Именованные объекты `node`, `way`, `relation`; для площадей используется центр объекта, а не вход.

SQLite: `backend/data/astana.db`. Сырой ответ и SHA-256 сохраняются в `backend/data/imports` и `import_runs`; `GET /api/data-status` показывает последнюю успешную загрузку. Неудачный запрос не заменяет старую базу. Полный успешный снимок атомарно обновляет объекты и удаляет отсутствующие в новом снимке. Дедупликация: OSM ID, затем одинаковое нормализованное имя/категория в пределах 35 м; предпочтение более полному объекту, далее стабильному ID. Это эвристика, возможны спорные соседние объекты.

Повторяйте импорт вручную перед демонстрацией, не запускайте частый опрос. Один ограниченный запрос, не более двух попыток на endpoint, задержки 10/5 секунд, до двух endpoint. [Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API), [правила тайлов OSM](https://operations.osmfoundation.org/policies/tiles/).

Для повторной обработки уже собранного настоящего снимка без сети, из папки `backend`: `..\.venv\Scripts\python.exe -m app.scripts.import_pois --from-snapshot data\imports\<имя-снимка>.json`. Источник такого запуска записывается как `snapshot:...`, сохраняется исходный OSM timestamp и SHA-256. Это явное восстановление из собранных данных, не автоматическая подмена при сетевом сбое; не используйте test fixtures.

Данные © OpenStreetMap contributors, [ODbL 1.0](https://www.openstreetmap.org/copyright). Импорт означает получение данных сообщества, не проверку на местности. Локальная база и сырые снимки исключены из Git; новый checkout требует импорта. При распространении снимка сохраняйте атрибуцию и выполняйте условия ODbL.

Если Codex-песочница блокирует сеть, localhost или временные каталоги, запуск тех же команд из обычного PowerShell решает ограничение окружения. Не обходите ошибки через загрузку вымышленных POI.

## Стек и структура

React 19 + TypeScript + Vite 8, React Leaflet 5 / Leaflet, Lucide, локальный Golos Text, официальный `@supabase/supabase-js`; FastAPI, Pydantic, SQLAlchemy, SQLite, HTTPX, Google Gen AI SDK. Рабочие версии закреплены в `package-lock.json` и `backend/requirements-lock.txt`. Гостевой локальный подбор работает без облачных сервисов; аккаунт требует существующий Supabase project, маршруты — openrouteservice.

`backend/app` — API, схемы, ORM, импорт и RAG; `frontend/src` — интерфейс, словарь `i18n/ru.ts`, карта; `scripts` — Windows-команды; `docs` — архитектура, RAG, сценарии, ограничения и материалы защиты. Часть серверных объяснений пока на русском; добавление kk/en потребует локализации backend.

## Ограничения первой версии

- Пешеходные маршруты требуют ORS_API_KEY. Нет проверки фактического состояния переходов, погоды, событий, билетов, реального наличия мест или качества заведений. Велосипедная дорожная маршрутизация не реализована.
- Дорога: расстояние по прямой × 1,3 / условная скорость. Пешком 80 м/мин, велосипед 220 м/мин. Визит: 15–45 минут по категории. Это оценки, не гарантия достижимости.
- Расписания: только `24/7` и простые непересекающиеся дни/диапазоны `Mo-Fr 09:00-18:00; Sa-Su off`. Праздники, ночные смены и сложные правила считаются неизвестными.
- Запросы понимаются по ограниченному словарю и правилам. Простые отрицания, сочетания и время поддерживаются; сложный контекст, опечатки, сравнительные ограничения времени и диалог могут быть не распознаны. Явные фильтры надёжнее.
- Gemini генерирует выбор и комбинацию проверенных смысловых фрагментов; свободный фактический текст намеренно не отображается.
- Это локальное приложение; публичное развёртывание не выполнялось. Есть Supabase Auth/RLS migration и ограничения нагрузки backend на процесс. Для production нужны HTTPS, разрешённые origins/redirects, настроенный routing, проверенная RLS и общие квоты для нескольких workers.
