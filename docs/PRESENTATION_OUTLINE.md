# Защита на 5–7 минут

**0:00–0:45 — проблема.** «Есть час в Астане, но поиск мест не отвечает, что реально успею рядом». Показать цель: короткий выбор из реальных данных, ясные причины и границы уверенности.

**0:45–2:45 — живая демонстрация.** Открыть карту; выбрать Mega из собственной выгрузки, 60 минут, прогулку. Показать карточку, метку, расстояние по прямой и источник. Переключить на 30 минут. Затем кафе для работы: показать честное предупреждение о неизвестных условиях. Не обещать конкретные результаты заранее — проверить текущую базу до выступления.

**2:45–3:45 — автоматический сбор.** Показать CLI-команду, фактический лог, сырой JSON, SHA-256 и время последнего импорта. Объяснить, почему данные собраны участниками автоматизированно, а не вручную сочинены. Сохранить evidence; показать OSM attribution.

**3:45–4:45 — RAG.** SQL-география + категории/текст + бюджет времени → реальные кандидаты → Gemini → проверка ID и допустимых объяснений → карточки. Показать подпись Gemini только при действительно успешном API-вызове. Показать fallback без ключа как предусмотренный режим надёжности.

**4:45–5:30 — качество и этика.** Отдельно факты, оценки и предложения; неизвестные часы; нет истории перемещений. Показать реальные результаты тестов из VERIFICATION.md. Не придумывать метрики пользователей, точности или производительности.

**5:30–6:30 — ограничения и развитие.** Маршрутизация по пешеходной сети, полевые проверки данных, расширение NLP/локализации. Сделать акцент на полезности и фактической достоверности.

Роли четырёх участников: продукт/демо, импорт/геоданные, backend/RAG, frontend/QA. До выступления каждый должен уметь объяснить соседний слой и ограничения. Держать запись живого прохода как резерв при сбое сети, честно называя её записью.
