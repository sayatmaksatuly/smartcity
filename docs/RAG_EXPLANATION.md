# Как работает RAG после Phase 2

1. **Intent processing.** Pydantic проверяет вход. `intent.py` выделяет категории, основные интересы, простые отрицания, прогулку/отдых, бесплатность, открытие и время. Есть ограниченные словари ru/en/kk. Категории из фильтра имеют приоритет над текстом с видимым предупреждением. Явное время сохраняется; распознанное другое время предлагается подтвердить. Если API не передал длительность, используется время из текста, иначе 60 минут. Совпадение названия старта с реальными алиасами OSM возвращается отдельно для подтверждения; координаты автоматически не меняются.
2. **Geographic retrieval.** SQL bounding box, затем Haversine. Исключаются несовместимые категории, платность/неизвестная платность при free_only, неподходящий outdoor, известное закрытие, неизвестные часы при open_now и превышение бюджета. Бюджет = посещение + округлённая оценка дороги × 1 или 2. Визиты остаются оценками по категории (15–45 минут); часы проверяются сейчас, не по времени прибытия. Никакой фильтр не ослабляется ради непустой выдачи.
3. **Ranking.** Прогулка повышает приоритет парков; отдых — парков/кафе. Для туристического запроса различаются monument, memorial, viewpoint, attraction и artwork; документированная идентичность wikidata/wikipedia/heritage усиливает релевантность. Внутренние аттракционы получают меньший вес. Точное положительное упоминание имени учитывается отдельно от упоминания старта. Добавляются близость и запас времени. Это эвристика, не рейтинг качества/популярности. Ничьи разрешаются расстоянием и стабильным ID. До 12 кандидатов сохраняют хотя бы одного представителя каждой доступной запрошенной категории; повторные близкие алиасы отфильтровываются.
4. **Gemini context.** Только реальные найденные ID, имена, категории, ранг, основание соответствия, расстояние по прямой, оценки времени, разрешённые причины и действия. Вместо сырого текста запроса передаётся структура намерений. Точных пользовательских координат, упомянутого старта, телефонов и произвольных описаний OSM в контексте нет. По кандидатам и расстояниям провайдер всё ещё может приблизительно понимать район поиска.
5. **Structured generation.** Официальный `google-genai`, `GenerateContentConfig(response_json_schema=GeneratedPlan.model_json_schema())`, 20 секунд, одна попытка SDK. Полная JSON Schema сохраняет `additionalProperties: false`; ответ заново проверяется через `GeneratedPlan.model_validate_json`. Модель выбирает 1–3 кандидата и коды объяснений/действий. Имена POI считаются недоверенными данными. Указания модели не заменяют серверную проверку.
6. **Grounding.** Pydantic запрещает лишние поля. Валидатор отклоняет неизвестный ID, повтор ID/близкого алиаса, повтор причины, недопустимую причину или действие. Если доступны две-три основные запрошенные категории, выбор должен их покрывать. При нарушении весь ответ заменяется локальным подбором. Имя, адрес, часы, источник и факты берутся из ORM. Объяснение всегда содержит расстояние и бюджет; соответствие интересу добавляется при подтверждённой категории, дополнительные коды — только разрешённые. Свободные фактические фразы модели не отображаются.
7. **Fallback и UI.** Нет ключа, ошибка/таймаут, неверный JSON или неподтверждённый выбор → стабильный локальный подбор. Сначала релевантность, затем покрытие доступных основных интересов и разнообразие. UI показывает «Подбор без ИИ», применённые условия, неопределённости и предложения подтверждения. Пустая выдача не подменяется фиктивными местами. Каждый результат — отдельный вариант, а не совместный маршрут.

Это retrieval-augmented constrained generation: Gemini выбирает реальные POI и проверяемые смысловые фрагменты. Свободная стилистика ограничена ради достоверности. Наличие LLM не делает правила понимания текста универсальными: сложные отрицания, опечатки, разговорный контекст и произвольные ограничения остаются вне гарантированного покрытия.

Тесты используют настоящие SDK-типы и настоящий сериализатор SDK с подменой HTTP-транспорта. Проверяются JSON Schema на проводе, запрет лишних полей, grounding и отсутствие приватных значений в диагностике. Ошибки разделены на `call` (SDK/API/таймаут), `parse` (пустой, обрезанный, заблокированный, неверный JSON или нарушение схемы) и `grounding` (неподтверждённые POI/причины/действия). Лог содержит только стадию, фиксированный код и числовой HTTP-статус; API сохраняет совместимый `fallback_reason=generation_failed`.

Реальный `mode=gemini` подтверждён через HTTP 17 октября 2026 с существующим серверным ключом и моделью `gemini-flash-latest`. [Причина ошибки и результаты](VERIFICATION.md). [Документация официального SDK](https://googleapis.github.io/python-genai/).
