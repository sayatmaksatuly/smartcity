# Сценарии ручной проверки

Перед проверкой: запустить импорт и оба сервера. Результаты меняются с содержимым OSM и текущим временем; не фиксируйте названия как обязательный ожидаемый ответ.

| Сценарий | Ввод и старт | Ожидаемое поведение | Проверка |
|---|---|---|---|
| A: Mega Silk Way | Найти `Mega` в поле старта, выбрать реальный OSM-объект; «Я возле Mega Silk Way, хочу погулять 30–60 минут»; фильтр 60 мин | 1–3 ближайших доступных по времени варианта или честный пустой ответ. Текст не меняет выбранный старт | Сравнить метки с OSM; сумма посещения и оценок дороги ≤60. Повторить с 30 |
| B: Работа в кафе | Старт в центре; «Найди тихое кафе рядом, где можно поработать» | Кафе, предупреждение, что тишина/розетки/места неизвестны | Нет обещаний Wi-Fi без тега, свободных столов или тишины. Источник каждой карточки доступен |
| C: Два часа | Старт в центре; «Хочу посмотреть необычные места»; 2 часа, архитектура | До трёх реальных достопримечательностей; отдельные варианты | Изменить время, выбрать карточку и метку в обратную сторону; ID, название и позиция совпадают |
| D: Неизвестные часы | Выбрать объект без opening_hours; обычный подбор, затем «Открыто по расписанию OSM» | Сначала может появиться с предупреждением; при строгом фильтре исключается | Не обещается открытие. Сложные строки PH/ночные интервалы → unknown |
| E: Без сети/ключа | Пустой GEMINI_API_KEY, импорт уже есть | Локальный режим без ИИ; карточки доступны, подложка без сети может отсутствовать | Не появляется «Подобрано Gemini». Сломанный backend даёт понятную ошибку и повтор |
| F: Пустая база | Отдельная тестовая DATABASE_URL, не удалять рабочую базу | Инструкция импорта, нет фальшивых карточек | Поиск отключён, после импорта «Проверить данные» обновляет состояние |
| G: Конфликт | Мало времени + культура, либо free_only без fee=no | Честный пустой ответ с предложением изменить условия | Нет автоматического ослабления фильтра |
| H: Мобильный | 360, 390, 760 px; поиск, карточка, карта, возврат к списку | Нет горизонтального скролла, выбранная карточка видна на карте | Доступны кнопки, источник, изменение точки и длительности |

Автоматизация: pytest — изолированная временная SQLite и явно синтетические fixtures. Playwright сам запускает настоящий локальный API (8001) с временной тестовой базой и Vite (5174). Имена сценария Mega в этих тестах — явно тестовые данные, не проверка наличия Mega в живом OSM. Сетевые подмены API используются для ошибок/пустого состояния; тайлы заменены для снижения нагрузки OSM. Живые данные проверяются отдельно `scripts/smoke.py`, карта — в браузере.

Phase 2 также проверяет смешанные интересы и отрицания на ru/en/kk, 40 минут и приоритет выбранного времени, предложение старта без автоматического переноса, приоритет категорий, неизвестные часы, невозможный бюджет, плотный набор парков, не вытесняющий запрошенное кафе, отказ Gemini при пропущенном интересе/дублях/лишних фактах, отсутствие исходного запроса в контексте. E2E покрывает подтверждения, видимый конфликт, фокус на результатах, перекрывающиеся метки, ошибку тайлов и повтор, отказ геолокации и сигнал offline.

Новые ручные сценарии: «кофе и погулять» → разные соответствующие варианты; «не хочу кафе, лучше парк» → исключение кафе; выбранное «Кофе» + тот же текст → предупреждение и сохранённый фильтр; «Я возле Mega Silk Way, у меня 40 минут» → две независимые кнопки подтверждения. Без подтверждения старт и 60 минут не меняются.

Для геолокации вручную проверить разрешение и отказ. Автоматические тесты не должны запрашивать или записывать настоящее положение участника. Для успешного Gemini добавить действующий ключ и убедиться, что ответ имеет `mode=gemini`; это отдельная внешняя проверка.
