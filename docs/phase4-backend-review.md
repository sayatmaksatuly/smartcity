# Phase 4 — backend integration, security and reliability review

Проверка: 17 октября 2026. Независимая роль субагента `backend_review`; это техническое ревью и фактические автоматические проверки, не пользовательское исследование.

## Проверенные границы

Прочитаны AGENTS.md, ARCHITECTURE, PHASE2_REPORT, PHASE3_REPORT, VERIFICATION, frontend API/типы/чат и основные компоненты, FastAPI-схемы, chat/recommendations pipeline и существующие тесты. Backend, SQLite-схема, импорт и секреты этим ревью не изменялись. Не запускались импорт Overpass, миграции, добавление fixtures в рабочую базу и Git push.

## Контракт, который должен сохраниться

- Все три пути используют `/api/recommendations` и существующий `/api/chat`; нового AI endpoint нет.
- Время 15–240 минут, запрос до 600 символов, максимум три результата, шесть категорий. Координаты остаются в React и теле запроса.
- `ChatContext` содержит типизированные предпочтения и ограниченные OSM ID, без transcript, координат и фактов. Видимые сообщения хранятся в памяти вкладки, максимум восемь.
- Изменения условий отменяют запрос и сбрасывают устаревшие результаты. Проверка идентичности AbortController не позволяет позднему ответу восстановить старый результат.
- `overrides` передают явные изменения UI. Отрицания, бюджет времени, уточнения «ещё», «ближе» и возврат остаются в существующем pipeline.
- Название старта из текста предлагает реальные SQLite POI, но не меняет позицию без `confirm_origin`. Выбор прошлого результата повторно проверяет его по текущим ограничениям.
- `mode=local` должен явно обозначаться как подбор без ИИ. `availability` различает open/closed/unknown; неизвестная цена не означает бесплатный вход.
- `straight_line_m` — расстояние по прямой, а `travel_minutes_estimate` — оценка; карточки являются отдельными вариантами, не дорожным маршрутом.
- Сохраняются `response_json_schema=GeneratedPlan.model_json_schema()`, `extra="forbid"`, whitelist ID/reasons/activities и независимая grounding validation. Сырой запрос и точные координаты не отправляются Gemini.
- Произвольный текст SDK exceptions и сырой вывод модели не попадают в логи; `/api` не содержит административного импорта.

## Среда и ограничения проверки

Первые sandbox-запуски pytest не завершили тесты: стандартный TEMP не позволил создать numbered directory; повтор с workspace basetemp завис на TestClient. Оба остановлены, результатом PASS не считаются. После разрешённого запуска вне Windows sandbox полная исходная команда завершилась успешно. Sandbox также не видел существующий localhost8000; read-only проверка вне sandbox подтвердила работающий API.

Для широкого smoke поднят отдельный loopback API8003 с пустым `GEMINI_API_KEY` только в окружении процесса, `--no-access-log`, скрытым окном и той же существующей базой. `.env` не редактировался. Основной сервер8000 оставлен без изменений. Тесты pytest используют временную SQLite с synthetic fixtures; рабочая SQLite fixtures не получает.

Два предупреждения pytest прежние: Google SDK `_UnionGenericAlias`/Python3.17 и Starlette TestClient/httpx2. Данные содержат 416 объектов без часов, 56 с неподдерживаемым расписанием и только один `fee=no`. Аудит проверяет согласованность источников и структуры, не истинность всех свойств на местности. Две успешные генерации подтверждают доступность Gemini во время проверки, не гарантируют будущую доступность API.

## Проверка после реализации

Независимо повторно прочитаны App, CityMap, ResultCard, api и useCityChat. Контракт API и существующий hook чата сохранены; карта создаётся через lazy import только после действия пользователя. Координаты и исходные сообщения не добавлены в URL, browser storage, телеметрию или журналы.

Проверены SHA-256 всех **17 Python-файлов backend/app** относительно снимка начала ревью: **0 изменённых файлов**. Повторный аудит рабочей SQLite после frontend-реализации: **549 POI**, прежние количества по всем шести категориям, **0 нарушений** источников, bbox, дедупликации и классификатора; последний import_run по-прежнему содержит 554 исходных объекта / 549 POI. Это проверка содержательных инвариантов базы, не заявленная проверка побайтовой идентичности SQLite-файла.

На промежуточной реализации обнаружены и переданы основному инженеру дополнительные ошибки переходов:

1. Сохранённое уточнение старта из чата вызывало скрытый chat request при выборе старта на главной и стирало новый поисковый черновик. Возобновление чата теперь ограничено соответствующим экраном.
2. Browser Back не очищал намерение показать выбранное историческое место; поздний ответ мог снова открыть карту. Теперь переход назад, новый запрос и инвалидирование очищают это намерение.
3. Ответ чата без recommendation_response мог оставить экран результатов без причины. Теперь соответствующее сообщение помощника видно в результатах.
4. Возврат на карту повторно центрировал выбранную точку даже после пользовательского перемещения карты. Теперь центрирование проверяет изменение выбора.

Ранее переданные проблемы случайного изменения старта и неправильного отображения `closed` также исправлены. Эти изменения выполнены основным frontend-инженером; ревьюер frontend-файлы не изменял.

Проведён фактический targeted browser-review через Playwright / Microsoft Edge, 1440×1000, frontend5175. Все `/api` запросы перенаправлялись на read-only fallback8003 с реальными OSM-данными; **новых Gemini-вызовов не было**. Команда: `node .runtime/phase4-integration-review.cjs`, exit0.

Первые два служебных запуска browser-review не смогли загрузить недоступный frontend5173; они не считаются успешными проверками. После указания действующего frontend5175 целевой прогон завершён успешно. Ни сырой текст запросов, ни координаты, ни сообщения исключений в вывод browser-review не включались. Процесс API8003 временно оставался для общей визуальной QA по согласованию с основным агентом; после завершения скриншотов и проверок он остановлен.

Остановлены только эти два QA-процесса. Порт8003 больше не слушает; существовавший API8000 PID1884 продолжает слушать. Дополнительные тесты или Gemini-вызовы при cleanup не выполнялись.
