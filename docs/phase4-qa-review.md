# Phase 4 — независимая QA-проверка

Дата: 17 октября 2026. Роль: QA Automation Engineer, отдельный субагент. Это инженерная проверка и экспертная оценка интерфейса; реальные пользовательские интервью не проводились.

## Среда и безопасность данных

Использован существующий Playwright с установленным Microsoft Edge (`channel: msedge`), один worker, реальные действия браузера. Конфигурация запускает `backend/tests/e2e_server.py` на 8001 и Vite на 5174. Сервер создаёт одноразовую SQLite через `TemporaryDirectory`, импортирует только явно тестовые места и отключает Gemini. Production SQLite и `.env` этим агентом не открывались и не изменялись.

Тайлы OSM в повторяемых E2E заменены однотонным SVG. Искусственные координаты предоставлены только для явного теста кнопки геолокации. Проверки ошибки 503, отсутствия данных и отказа тайлов используют ограниченные сетевые подмены; обычные рекомендации и диалог работают с настоящим backend и disposable SQLite. Эти тесты подтверждают локальный fallback, но не доступность внешнего Gemini. Проверки реальных 549 мест и живых тайлов выполнены отдельно главным агентом и описываются в общем аудите.

Первый sandbox-запуск не смог создать временную SQLite в Windows sandbox TEMP. Запуск Edge и локальных тестовых серверов успешно выполнен через разрешённое расширенное исполнение; production данные не задействовались.

## Фактические запуски

| Запуск | Фактический результат |
|---|---|
| Исходный UI: разовое снятие baseline | 1 passed, 6.7 s |
| Первый полный запуск адаптированных тестов | 25 passed / 8 failed из 33, 1.4 min |
| Полный повтор после исправлений и двух дополнительных регрессий | **35 passed, 1.1 min** |
| Финальное обновление screenshots после перестановки composer | **5 passed, 12.7 s** |

Команды: `npm --prefix frontend run test:e2e`; затем `npm --prefix frontend run test:e2e -- --grep "mobile chat and map|all primary views"`. Переходы, геометрия, состояния и network assertions проверены фактическим запуском, а не только чтением исходников.

В первом полном запуске пять сбоев были вызваны неоднозначным тестовым selector для внешнего `summary` и вложенного `summary`; исправлен выбор прямого потомка. Ещё один тест ожидал старую подпись кнопки во время loading. Synthetic offline event в одном тесте отправлялся до завершения lazy mount карты: добавлено ожидание видимой карты. Это семь исправлений тестового harness, а не изменения требований к продукту.

Восьмой сбой выявил реальную проблему accessibility: Escape закрывал диалог выбора старта, но не возвращал keyboard focus на кнопку, открывшую его. Главный агент исправил сохранение и восстановление focus в `Modal`; неизменённая проверка поведения прошла.

## Покрытые сценарии

- Главная: один явный CTA, три входа A/B/C, отсутствие начальной загрузки CityMap/Leaflet/OSM tiles и самопроизвольного запроса геолокации.
- A: запрос → до трёх мест → отдельное место/общая карта → назад; сохранены запрос, выбранное место и старт.
- B: выбор времени и интересов → существующий backend → результаты с применёнными условиями.
- C: память времени и отрицаний, предпочтение ближе, явное переопределение фильтров, новая тема и новый диалог.
- Chat/results/map синхронизированы; текущие и исторические места можно выбирать повторно. Повторный выбор возвращает выбранную метку в область просмотра.
- Браузерная кнопка Back возвращает map → results → home без потери запроса и рекомендаций.
- Панорамирование и zoom реальной Leaflet-карты → результаты → общая карта сохраняют экранное положение выбранной метки. Проверка сравнивает DOM-геометрию, не читает внутреннее состояние Leaflet.
- Обычный клик по подложке карты не меняет старт. Изменение происходит после явного выбора режима.
- Оставленный чат с запросом подтверждения старта не возобновляется скрыто при выборе старта на главной и не стирает новый черновик.
- Предложенные в тексте старт и время требуют подтверждения; просроченное подтверждение не переименовывает уже выбранный старт.
- Смешанные интересы и отрицания доходят до retrieval; явные категории имеют приоритет, конфликт заметен.
- Пустая база, отсутствие совпадений, loading, 503/retry, отказ геолокации, offline и сбой тайлов имеют проверенные состояния.
- Chat: пустой ввод, Shift+Enter, лимит 600 символов, duplicate send, retry, устаревший transport response, ограниченная история, неподдерживаемый запрос, явная маркировка «без ИИ».
- Keyboard: Enter запускает поиск, focus переходит к результатам, Escape закрывает диалог и возвращает focus.

Две дополнительные регрессии (сохранение viewport и отсутствие скрытого продолжения чата) закрепляют исправления, найденные независимым чтением исходников. Дублирующиеся DOM ID карточек в скрытом map aside исправлены главным агентом до итогового запуска.

## Размеры и доступность

На **320, 390, 768 и 1440 px** пройдены home/results/map/chat с реальными переходами и проверкой отсутствия горизонтального overflow. На каждой ширине основной CTA главной находится в первоначальном viewport. Высота — 844 px для трёх меньших размеров и 1000 px для desktop.

Проверка 200% выполнена настоящим рендерингом `document.documentElement.style.zoom = "2"` на desktop: поиск и результаты доступны, горизонтальный overflow отсутствует. Это **CSS zoom**, не утверждение о ручной проверке системного масштабирования или настройки zoom браузера. Полная сертификация WCAG, проверка screen reader и исследование с пользователями в данный QA-прогон не входили.

После замечания UX-проверяющего empty-chat composer перемещён перед подсказками. На свежем screenshot 390 px поле начинается примерно на y=539 и видно без первого длинного скролла; исходная новая версия помещала его ниже первого экрана. В заполненном диалоге остаётся вертикальная прокрутка истории и страницы — приемлемо для этой фазы, sticky composer можно оценить отдельно.

## Оценка QA до/после

| Критерий | До | После | Основание |
|---|---:|---:|---|
| Ясность первого действия | 4/10 | 8/10 | Прямой вопрос, большое поле и видимый CTA. Три дополнительных способа доступны; часть mobile journey links требует скролла. |
| Mobile и читаемость | 4/10 | 8/10 | На исходном 390×844 CTA был ниже экрана, старт обрезан, много 11–12 px текста. Теперь CTA виден, старт переносится, иерархия крупнее. Заполненный чат ещё требует заметной прокрутки. |
| Приоритет содержания desktop | 4/10 | 8/10 | Ранее карта занимала около 70% экрана и сжимала форму в ~440 px. Теперь запрос и результаты первичны, карта загружается по намерению пользователя. |
| Проверенность функциональной регрессии | Не оценивалась отдельным полным baseline run | 9/10 | 35 фактически прошедших тестов плюс финальные 5. Оценка ограничена controlled backend/fallback; Gemini и все production места этот suite не проверяет. |

Незакрытых критических дефектов в проверенных сценариях не осталось. Это не доказательство отсутствия любых дефектов за пределами перечисленного покрытия.
